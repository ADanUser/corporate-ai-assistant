# Корпоративный AI-ассистент

Учебный проект: внутренний помощник компании, который отвечает на вопросы
по документам, соблюдает права доступа и выполняет действия только с
подтверждением человека.

Написан на **Python + FastAPI**.

## Зачем этот проект

Это не «чат с GPT по документам». Проект показывает три инженерные вещи,
которые отличают безопасного корпоративного ассистента от простой обёртки
над языковой моделью:

1. **Права доступа проверяются кодом, а не промптом.** Документы фильтруются
   по роли пользователя ещё до поиска. Обычный сотрудник физически не может
   получить финансовый документ — модель его просто не видит.
2. **Опасные действия требуют подтверждения человека** (human-in-the-loop).
   Бот готовит черновик задачи и ждёт «approve», прежде чем что-то сделать.
3. **Всё логируется** (audit log). Любое действие можно объяснить постфактум.

## Роли

| Пользователь | Роль     | Что видит                         |
|--------------|----------|-----------------------------------|
| alice        | Employee | Общие документы (командировки, отпуск) |
| bob          | Manager  | То же, что Employee                |
| admin        | Admin    | Всё, включая зарплатные данные     |

## Как запустить

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Открыть в браузере: **http://localhost:8000/docs** — там удобная страница,
где все запросы можно потыкать мышкой.

## Демо-сценарии

1. **Ответ по документам с источником**
   `alice` спрашивает «как оформить командировку» → получает ответ + ссылку
   на источник.

2. **Отказ по правам доступа**
   `alice` спрашивает про зарплаты → «не найдено», потому что финансовый
   документ отфильтрован по роли.

3. **Тот же вопрос, но у Admin**
   `admin` спрашивает про зарплаты → получает данные. Разница только в роли.

4. **Действие с подтверждением**
   `bob` создаёт задачу → бот отдаёт черновик → `bob` подтверждает через
   `/approve` → задача «создаётся».

5. **Журнал**
   `GET /audit` показывает всё, что происходило.

## Архитектура (конвейер запроса)

```
Запрос → Кто пользователь (identity)
       → Фильтр по правам (permissions)   ← безопасность здесь
       → Поиск в документах (retrieval)
       → Ответ с источником  /  Черновик действия → Подтверждение
       → Запись в журнал (audit)
```

## Структура кода

```
app/
  identity.py       — кто пользователь (заглушка SSO)
  permissions.py    — проверка прав доступа (вне модели)
  retrieval.py      — поиск в документах + защита от prompt injection
  audit.py          — журнал событий
  data/documents.py — документы компании с метаданными доступа
  main.py           — FastAPI, связывает всё в конвейер
```

## Ограничения (честно) и что дальше

Это MVP для портфолио. В нём намеренно упрощено:

- **Поиск по документам** сейчас простой (по совпадению слов).
  Следующий шаг — заменить на настоящие эмбеддинги + векторную базу
  (Chroma/FAISS). Место замены помечено в `retrieval.py`.
- **Ответы** отдают текст документа напрямую. В полной версии текст ответа
  генерирует языковая модель на основе найденных фрагментов.
- **Вход (SSO)** — заглушка с тремя пользователями.
- **Jira-инструмент** — мок (возвращает фейковую ссылку).

## Как бы я довёл это до production

Подключил бы реальный SSO вместо заглушки, вынес документы во внешнее
хранилище с версионированием, добавил набор автотестов (evals) с
блокирующей метрикой: не выкатываю, если хоть один тест на права доступа
падает. Плюс мониторинг ошибок и задержек.
